# 08 困ったとき(FAQ・トラブルシューティング)

画面に出るメッセージを、そのまま検索してください。

## 起動・ログイン

| 症状 | 原因と対処 |
|---|---|
| `python` が見つからない | Python 3.12 を入れ、PATH を通す。Windows なら `py -3.12 -m ermdm serve …` |
| ページが開かない / 接続できない | サーバーのウィンドウが閉じていないか。URL は `http://127.0.0.1:ポート/`(`https` ではない)。他のPCからは繋がらない(仕様) |
| `Host header is not allowed`(403) | `127.0.0.1:ポート` か `localhost:ポート` 以外のホスト名で開いている。そのURLで開き直す |
| ログインできない | パスワードの間違い。`--admin-password` は**最初にデータフォルダを作ったときだけ**有効。忘れたら、別の `--data` で作り直す(⚠ 既存データのパスワードを再設定する機能は無い)。他のユーザーなら、管理者が `useradd` で作り直す |
| 勝手にログアウトされる | 12時間で期限切れ。または別ポートのアプリで同じ `127.0.0.1` にログインした(Cookie共有) |
| 画面が空白・古い | `Ctrl+F5` で再読み込み |
| 文字化けする | CSVは UTF-8(BOMつき可)か Shift_JIS(CP932)。それ以外(UTF-16、EUC-JP など)は「文字コードを判定できません」で止まる。変換してから取り込む |

## 取り込み

| メッセージ | 原因と対処 |
|---|---|
| `CSVが空です` / `空の列名があります` / `列名が重複しています` | CSVの1行目(列名)を直す |
| `キー '…' が重複しています` / `N件目: キー(列名)が空です` / `キー列 … が入力にありません` | キー列は一意で空でなく、CSVに存在すること。重複を除くか、別のキー列を選ぶ(キーが無ければ、行番号の列を足す) |
| `スキーマが変わったため取り込みを停止しました` | 列が増減した。ソース一覧の「承認」で内容を確認してから再取り込み。意図しない変更なら、データ提供元に確認 |
| `列 … は個人番号と判定されたため、キー/正解列に使えません` | 個人番号らしい列をキーや正解列にしている。別の列にする |
| 隔離列が出た | 個人番号と判定されて**保存しなかった**列。不要なら対処不要。必要な列を誤検出したときは、列名や値の形を変えて再取り込み(⚠ 解除の機能は無い) |
| 「同名のソースがあります」 | ソース名は一意。別の名前にする |
| 取り込んだのに件数が増えない | 「変更なし」なら、同じ内容を入れただけ(冪等で正常) |
| 取り込んだら件数が減った | **スナップショット**はファイルに無い行を削除扱いにする。差分のつもりなら「差分」を選ぶ |

## 設定・学習

| メッセージ | 原因と対処 |
|---|---|
| `有効な標準化設定がありません` | 「設定」で標準化を「版として保存」していない |
| `ブロッキングルールが未設定です` | 「ブロッキング・閾値」で `rules` を入れて「保存」していない |
| `候補ペアがありません。ブロッキングを見直してください` | ルールに合う組が1つも無い。キーの項目名の綴り、標準化で値が空になっていないか(プレビュー)を確認 |
| 保存で `未知の操作: [...]` | `ops` の綴り。使える操作は「設定」画面の「操作:」に並ぶ |
| 保存で `標準化設定には fields…` / `フィールド名が空または重複` | JSON の形。[06](06-config-reference.md) を見る。カンマや括弧の閉じ忘れは、ブラウザで JSON を貼ると見つかる |
| `個人番号として隔離された列は照合に使えません` | `sources` に隔離列を書いている。除く |
| `未学習のモデルは有効化できません` | 先に「学習」を押す(決定的ルールのみのモデルは不要) |
| `同一性の定義は10文字以上で…` | 定義の文章を、粒度と時間の扱いも含めて10文字以上で書く |
| 学習すると λ が 1.000 付近 / 確認キューが空 | ブロッキングが絞りすぎで、「別」の組が候補に無い。ルールを緩める([04](04-your-own-data.md)) |
| 標準化を変えた後、結果がおかしい | モデルは**学習したときの標準化**に基づく。標準化を変えたら、モデルを再度「学習」して「有効化」する(⚠ 推奨。自動では再学習されない) |
| `0 ≤ 確認下限 ≤ 自動マージ閾値 ≤ 1 である必要があります` | `thresholds` の大小関係 |

## 実行

| メッセージ・症状 | 原因と対処 |
|---|---|
| `有効なモデルがありません(作成して学習し、有効化してください)` | 「設定」のモデル: 保存 → 学習 → 有効化 |
| `モデルが未学習です` | 同上。「学習」を押す |
| `ガバナンス上の理由で実行できません: ソース … は個人データを含みますが、有効な利用目的…` | 個人データのソースに利用目的が紐づいていない。「ガバナンス」で登録し、ソースに紐づける(→ [07](07-operations.md)) |
| `候補ペアの見積(N件)が上限(M件)を超えるため停止しました` | ブロッキングが緩すぎる。キーを足して絞る(AND)か、`max_block` を下げる。見積は「設定」の「候補ペア数を見積る」で事前に確認できる |
| `別の実行が進行中です` | 実行は1つずつ。終わるのを待つ |
| 実行が `failed` | 一覧の上の赤いメッセージ、または「実行」の履歴を確認 |
| 実行が終わらない | 数万件以上では、純Pythonのため遅い(⚠ 規模は未測定。→ [09](09-limitations.md))。候補ペア数が多すぎないか、見積で確認 |

## 結果の見方

| 疑問 | 答え |
|---|---|
| 同じ会社なのに別々のIDになっている | ①標準化で表記が揃っていない(「設定」→「プレビュー」で2件を確認) ②ブロッキングで候補に入っていない(評価の PC、ルール別寄与)。③確率が閾値に届かない(確認キュー・評価で見る) |
| 別の会社が同じIDになっている | 連結成分は、鎖でつながる別人を1つにする。**エンティティ詳細で分割**する。多発するなら `clusterer` を `center` にする、決め手の項目を足す、自動マージ閾値を上げる |
| 確認キューが0件 | 中間(確認下限以上、自動マージ未満)の組が無い。または学習が壊れている(λ)。閾値を調整して確認帯を広げる |
| 確認キューが多すぎる | 見積(「確認キュー」の上)で、閾値ごとの量を見て調整。人手の判定結果を、ラベルとして評価に使える |
| 分割したら、新しいIDが「選んだ点」ではなかった | **大きい方のグループが元のIDを引き継ぐ**仕様 |
| 判定を直したい | 画面では、判定済みの項目は再判定できません。APIで同じ項目に別の判定を送ると、**制約が上書き**されます(✅ 確認): `POST /api/review/{id}/decide` `{"decision":"match","reason":"…"}`。分割の取り消し(再統合)の機能はありません(⚠) |
| 評価に「正解付きデータでの閾値曲線」が出ない | ソースに正解列が無い。サンプルを作ってラベルを付ける |
| PCが低い | ブロッキングで本当の一致を落としている。キーの種類を足す(和集合)、`prefix` で緩める |
| 適合率は高いが再現率が低い | PC(上限)が低いか、自動マージ閾値が高すぎ。評価の曲線で、再現率が頭打ちになる位置がPC |

## 画面の不具合

| 症状 | 対処 |
|---|---|
| ボタンを押しても何も起きない | 画面上部・ボタンの下の赤いメッセージを見る。権限が無い(403)ことが多い |
| グラフが出ない | ブラウザの JavaScript を有効に。アプリは d3.js を同梱しており、外部通信は不要 |
| 画面が崩れる | Chromium 系で確認済み(✅)。Chrome / Edge は同系統の想定(⚠)。Firefox / Safari は未確認 |

それでも解決しないとき: サーバーを起動したウィンドウに出ているログ(1行ごとのJSON。時刻・メソッド・パス・ステータス・ユーザー・所要ms)を確認してください。5xx(内部エラー)は、スタックトレースが出ます。**個人データを含まないよう注意して**報告してください。
